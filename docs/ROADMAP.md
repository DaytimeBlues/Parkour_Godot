# Godot port roadmap

Implement one reliable fox course before expanding species, scenery or networking systems.

1. **Preserve exact source and recovery.** Keep the selected woodland project, stable fallback and separate labs identifiable. Complete the outstanding student-input recovery gate through an authorized route; do not bypass a denied check or discard its failures.
2. **Diagnose browser HTTP completion.** Follow one request through sample, dispatch, server response, Fetch reader, Godot callback, acknowledgement and next heartbeat. Compare one variable at a time, beginning with externally verified foreground versus background/occluded scheduling. Keep the original 1,000 ms server idle guard and sequence/epoch/revocation rules.
3. **Prove continuous authoritative movement.** Exercise hold/release, idle heartbeat, lost/delayed replies, focus loss/return, re-arm, pause/resume, reconnect, changed epoch and revoked seat. No endless reconnect loop or stale-input resurrection. Native checks do not replace ordinary browser input.
4. **Integrate the proven fox animation only after rights and integration review.** Validate scale, +Z facing, wing socket, independent pose, loop timing, speed-based blending and jump/climb/glide/dive/landing transitions. Resolve floor penetration and foot contact rather than concealing them.
5. **Complete one representative course.** Start, route choice, climb/jump, glide, safe landing, checkpoint, failure/retry, finish and reset. Use woodland/cream-stone contrast and clear landing space. Test camera compression near pillars and doorways.
6. **Validate networked play and destination.** First two rendered clients, then the intended class size and real school hardware/network. Choose and authorize hosting separately. Keep the original Three.js game as behavioral reference and rollback source.

Visual direction: distinct matte fox silhouette, readable wings, connected woodland and cream-stone route, simple objective/join feedback. Generated images are visual references, never rigging, geometry or acceptance evidence. The later full animal roster is not a prerequisite.

For each milestone distinguish source implemented, imported, ordinary runtime checked, visually accepted, recovered, hosted checked and classroom accepted. Record exact source/build identities and limitations.
